# Corredor Invertido

Browser endless runner (pseudo-3D tunnel), shipped as a PWA on GitHub Pages from `main` (root). No build step, no dependencies: static files and native ES modules.

## Conventions

- Keep `js/sim.js` free of drawing and audio. It reports events through `emit(type, data)`; `main.js` routes them to `audio.js`. The renderer (`js/render.js`) only reads state.
- `js/lyre.js` is shared with the `guilhermrosa/lira-de-bolso` repository. Keep both copies identical; change one, copy to the other.
- When adding or renaming a file the game loads, add it to `SHELL` in `sw.js`.
- On every release, bump `APP_VERSION` in `js/version.js`, the only copy of the version: the menu label and the service worker cache name (`sw.js` imports it) both read it.
- Privacy (v0.38 / v0.6.2, user request): nothing leaves the device, so no consent screen is needed. Fonts are served from `fonts/` (latin subset woff2, OFL licences alongside) instead of Google Fonts, so the app contacts no other site (the service worker only handles same-origin requests). `privacidade.html` explains this in plain pt-BR (what stays on the device, how to delete it, hosting by GitHub Pages, no permissions, and the optional feedback form); it is linked from the menu and is the privacy policy URL a store listing will need. Keep it true when adding features that store or send anything (e.g. the planned microphone/audio-file feature of the Lira).
- Commits (user request, 2026-11-13): author and committer are the user, `guilhermrosa <57267848+guilhermrosa@users.noreply.github.com>` (GitHub's no-reply address, so the personal e-mail stays private), set in this repository's `.git/config`; no `Co-Authored-By` or `Claude-Session` lines in commit messages. The whole history was rewritten that way, dates and contents unchanged. In a fresh clone, set `git config user.name` / `user.email` to those values before committing.
- Shared storage (learned 2026-11-13): every GitHub Pages project of the user lives on the same origin, `guilhermrosa.github.io`, so the Corredor and the Lira share one localStorage. The user cleared that site's data in Chrome and lost everything in both apps (game stats/record, and likely the Lira's saved recordings). Decision: no backup or own domain for now; it is solved when the apps become store apps with Capacitor (each app gets its own storage). Until then, warn before telling the user to clear site data.
- UI text is in Brazilian Portuguese.
- Test with a local server (`python3 -m http.server`); modules do not load from `file://`.
- Automated tests (v0.35): `npm test` (or `node --test`), Node 22+, no dependencies; `package.json` exists only for this. `tests/solver.js` is a brute-force player over the real sim (nothing / tap / swipe down every 50 ms, strict: slipping into a hole counts as failing). Tests prove every authored stretch at 12/16/21 m/s from both surfaces, random generator windows from 100 to 2000 m, every tutorial step, and the rules (hole grace, lives, golden heart). Run them after any change to sim.js, config.js, sequences.js or tutorial.js; a new obstacle or stretch must keep them green.
- Visual history (`docs/evolucao/`, user request): a gallery page (served by Pages at /docs/evolucao/) with menu / floor / roof screenshots per milestone version, from the 0.5 greybox prototype (taken from the old Corredor artifact) on. On every release with a visible change, run `node tools/capture-versions.cjs <version>=HEAD` (Playwright; fixed random seed, same inputs for every version) and add an entry (version, date, pt-BR title and text) to `docs/evolucao/versions.json`. Not part of the game: keep these files out of `SHELL`.
- Art direction test (`prototipos/estilos/`, not part of the game, keep out of `SHELL`): the real sim and touch controls drawn with neutral shapes in the two candidate looks the user is weighing, since all current art is placeholder: A `?estilo=retro` simple 3D polygons at ~146×260 px, Bayer dithering to a 10-colour palette plus grain (rolling camera); B `?estilo=papel` 2.5D paper cut-outs (cards with a white cut edge and a drop shadow that fold up from their surface as they approach, a paper-fibre texture multiplied over everything, fixed camera, the hero turning over like a card on a flip). Which way fits depends on how the user will make the final art (2D drawings → B; 3D models → A; pixel art → either). User verdict: the current placeholder look is better than both test renders; the exploration is parked for later. If the final look is 3D, the user cannot model: Claude builds the models in Blender on the user's computer (Blender Python scripts, run there via a connection to their machine). If it is paper-like, the user draws most of the assets.
- Code layout (v0.35): `main.js` = loop, game flow, menus and keys; `options.js` = Opções state, labels and buttons; `input.js` = touch gestures; `panels.js` = stats panel, achievements list and toast; `store.js` = localStorage wrapper; `sequences.js` = authored stretches (data).
